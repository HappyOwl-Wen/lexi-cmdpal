# 时间与空间复杂度优化（2026-10-23）

重点检查了搜索、SQLite 读取、词条编解码、数据导入及服务缓存。优化基线为 `cbd78d1c24721460c2522c41f2a6316b97bf8873`。现有 SQLite 索引、DAWG 持久化格式和词条二进制格式保持兼容，无需重建词典。

## 复杂度与实现

| 路径 | 原实现 | 修改后 |
|---|---|---|
| `FuzzyIndex.Search` | 每条展开的边计算整行，时间 `O(E(m+1))`；预先创建约 50 个行数组，工作空间 `O(L(m+1))` | 每行仅计算并存储距离带，时间 `O(Ew)`，工作空间 `O(min(L,m+k)w)`；常用距离 1/2 使用栈内存，大距离使用数组池 |
| `EditDistance.Osa` | 三个完整行，时间 `O(nm)`，工作空间 `O(m)` | 短串作为列，只保留三条距离带，时间 `O(nw)`，工作空间 `O(w)`；距离为 0 时直接比较 |
| `Utf8LineReader.TryReadLine` | 短读时反复扫描尚未完成的整行，最坏可达 `O(N²)` | 记录本次已扫描位置，每个字节只扫描一次，扫描时间 `O(N)`；保留原来的缓冲区压缩和扩容机制 |
| `EntryCodec` | 每次编码分配最大压缩缓冲区，每次解码分配完整解压缓冲区 | 小词条跳过压缩缓冲区；其他词条从数组池借用，`finally` 归还；渐近空间仍为 `O(B)`，减少的是重复分配和 GC 压力 |
| `AiCache` | 内存随不同请求数 `U` 增长，过期对象仍可能被保留 | 哈希表加链表实现 128 条 LRU，命中、更新、淘汰均为平均 `O(1)`；内存最多保留 128 个答案，过期命中立即移除，淘汰后仍可从磁盘读取 |

其中 `k` 是允许的编辑距离，`w = min(m+1, 2k+1)`；OSA 的 `n`/`m` 分别为长串/短串长度，模糊搜索中的 `m` 为查询长度、`L = 48` 为最大键长。`E` 指本次遍历展开的边数，共享状态可能沿不同前缀访问多次。表中的动态规划空间不含索引及必须返回的结果；AI 缓存按答案条数设上限，实际字节数仍取决于各答案长度。

另外，DAWG 构建器复用上一键的编码缓冲区，避免每加入一个键就分配数组；AI 请求排队后重新查缓存，避免同一答案已经生成后再次调用提供者。显式重新生成仍绕过缓存。

距离带同时保留换位需要的前两行，带外单元视为不可达，不会读取未初始化或上一个分支留下的单元。补修了原有的结果上限问题：深层递归达到 `maxResults` 后，上层立即结束，结果不再超出约定数量。负距离参数现在明确拒绝，极大距离参数不会在长度检查时溢出。

## 同机前后实测

环境：Ryzen 9 7940H、16 逻辑核、31 GB RAM、Windows x64、.NET 10.0.13，Release 构建；同一份 529 MB 词典，975,975 个词头、952,321 个模糊键。前后顺序运行，未并行运行性能测试。

`lexi bench --rounds 7 --sample 300`：各类查询预热后执行 7 轮，随机词头和错拼使用固定种子。完整查询包含规范化、SQLite 候选读取及排序。

| 查询类别 | p50 原 / 新（ms） | p95 原 / 新（ms） |
|---|---:|---:|
| 全部 | 1.57 / 1.47 | 3.04 / 2.75 |
| 拼写错误（274 条） | 1.88 / 1.56 | 3.03 / 2.33 |
| 精确查询（300 条） | 1.62 / 1.52 | 2.94 / 2.96 |
| 前缀（245 条） | 1.17 / 1.21 | 2.12 / 2.11 |
| 验收查询（34 条） | 2.95 / 2.99 | 9.51 / 6.73 |

独立热点微基准使用 `Stopwatch` 和 `GC.GetAllocatedBytesForCurrentThread`，每个工作负载预热 5 轮后测量；分配量包含必需的结果对象，不是进程常驻内存。

| 工作负载 | 原 / 新耗时（µs/次） | 原 / 新分配（B/次） |
|---|---:|---:|
| 真实 DAWG 查询，距离 1 | 277.49 / 156.76 | 5,726 / 942 |
| 真实 DAWG 查询，距离 2 | 1,244.31 / 625.84 | 13,814 / 9,024 |
| 长度 1,002 的 OSA，距离上限 2 | 2,369.10 / 21.06 | 0 / 0 |
| 20 个较长义项的词条编码 | 227.48 / 219.96 | 25,632 / 12,888 |
| 同一词条解码 | 75.29 / 77.72 | 20,768 / 8,032 |
| gzip 中的 3 MiB 长行 | 625.91 / 493.82 | 1,065,132 / 1,065,132 |

模糊查询为 `vulnerabilty`、`authentcation`、`schwachstele`、`bedorhung`、`teh`、`hauser`、`security`、`translatoin`、`abcdefghij` 及 48 个 `a`，各测 100 轮，结果上限 800。距离 2 的对比同时包含结果上限修复，旧版会多返回少量结果。OSA 为 1,000 个 `a` 后接 `bc` 与 `cb`，测 500 次；其动态规划缓冲区从 12,036 B 降为 60 B，旧版复用数组池，因此两者在预热后都无托管分配。编解码各测 1,000 次；长行每文件 4 行、测 12 轮。

完整查询 p95 下降约 9.5%，错拼查询 p95 下降约 23%；微基准中的模糊搜索耗时下降约 44%–50%。解码主要减少分配，耗时未显示改善。数组池会保留缓冲区用于复用，进程工作集也受 SQLite、文件缓存、JIT 和 GC 时点影响；本次测量不能据此声称进程常驻内存下降。冷启动和详情首次渲染受缓存影响较大，未计为本次收益。

原始输出和临时微基准程序保留在本机忽略目录 `artifacts/performance-before.md`、`artifacts/performance-after.md` 及 `artifacts/performance/`，其中 `Program.cs`、`Perf.csproj` 可用于重测热点。

## 验证

- 优化前：220 项测试全部通过；优化后：236 项测试全部通过，无跳过。
- 独立全矩阵 OSA 对照短串穷举、随机词典、距离 0/1/2、大距离、最长键、换位边界和结果截断，避免两个优化实现相互作为测试依据。
- 原样本输入在全部/英语/德语过滤下的结果 ID、匹配类型与分数摘要前后一致；真实词典 34 项排名验收全部通过。
- 覆盖原始与 gzip 文件的空行、中文、未终止行、CRLF 跨读取边界、缓冲区压缩与扩容。
- 覆盖不同大小词条反复编解码，及 AI 缓存淘汰、磁盘回读、过期、相同请求排队和明确绕过缓存；AI 测试使用本地假提供者。
- CLI 和 x64 Debug 扩展构建通过；扩展进程内自检 64/64，通过临时设置目录验证搜索、页面、详情、筛选、fallback 及发音逻辑。
